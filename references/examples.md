# 使用示例

## 示例 1：人物分析

用户：

> 为什么田文比吴起更适合做国相？

建议分析路径：

1. 先区分“个人才能”和“国相职位需要的能力”。
2. 比较军事/行政才能、协调能力、君臣关系和政治联盟。
3. 解释为什么能力更强不等于更适合最高协调岗位。
4. 联系魏文侯的用人逻辑。
5. 如有必要，再映射到现代组织中的专家型人才与整合型领导者。

---

## 示例 2：改革比较

用户：

> 为什么吴起死后改革失败，商鞅死后秦法还在？

建议输出：

- 共同点：强君支持、触碰既得利益、改革者个人遭反扑。
- 关键差异：政治环境、制度化程度、执行体系、新受益集团、继任者收益。
- 重点检查“改革是否形成了脱离改革者个人而继续运转的结构”。
- 不要简单归结为“秦国人更支持改革”。

## 示例 3：司马光视角

用户：

> 为什么《资治通鉴》开篇要讲三家分晋？

建议分析：

1. 事件本身。
2. 周威烈王承认韩赵魏诸侯地位的制度意义。
3. 司马光对“名分”的明确评论。
4. 为什么这个案例适合作为全书政治思想入口。
5. 再讨论这种秩序观的优点与局限。

## 示例 5：增量合并，而不是重复建笔记

Vault 已存在：

```text
人物/吴起.md
事件/吴起变法.md
概念/政治联盟.md
00-MOC/战国改革 MOC.md
```

新讨论得出：吴起改革失败还与权力交接时政治保护突然消失有关。

不要直接创建：

```text
概念/君主去世导致改革失败.md
概念/吴起失败原因.md
```

先生成 Merge Plan：

```text
UPDATE  人物/吴起.md
UPDATE  事件/吴起变法.md
DEFER   权力交接风险（如果目前只有吴起一个案例）
LINK    [[吴起变法]] --依赖--> [[楚悼王]]
```

之后读到商鞅案例，同一机制再次出现，再执行：

```text
PROMOTE 概念/权力交接风险.md
UPDATE  吴起变法.md
UPDATE  商鞅变法.md
UPDATE  战国改革 MOC.md
```

这体现“先作为案例内结论，跨案例复现后再升级为概念”。

## 示例 6：利用现有 7 个 Obsidian Skills

用户：

> 把今天关于吴起、商鞅和改革制度化的讨论合并到我的知识库，并更新地图。

推荐编排：

1. `tongjian-scholar`：抽取人物、事件、机制、关系。
2. `obsidian-cli`：搜索现有吴起/商鞅/改革/MOC/Canvas。
3. `llm-wiki`：辅助识别“制度固化”“制度化”是否为同一 canonical concept。
4. `tongjian-scholar`：确定 Merge Plan，不让近义词造成两个概念节点。
5. `obsidian-markdown`：更新 canonical notes。
6. `obsidian-bases`：如字段/视图受影响，刷新相关 Base。
7. `json-canvas`：仅增加新的结构关系，保持旧节点位置。
8. 校验脚本：检查 Vault 与 Canvas。

`knap` 在这里只在需要一次生成大量已确认节点时使用；`defuddle` 不需要，因为输入不是网页。
